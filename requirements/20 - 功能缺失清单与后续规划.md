# 功能缺失清单与后续规划

> 基于 2026-07-01 全项目审查整理，覆盖后端、前端、架构、文档四个维度。

---

## 一、代码中的 TODO / 明确未完成项

### 1.1 OpenAI 后端是桩代码

`backend/chat/agent/llm/openai.py` 仅作为 stub 存在，无法实际使用 OpenAI 兼容模型（GPT、DeepSeek、Gemini 等）。当前生产路径只支持 Anthropic Claude。

**影响**：用户被锁定在单一 LLM 提供商，无法利用其他模型的成本/性能优势。

### 1.2 向量语义搜索未接入 Agent

需求文档 6 明确将 `search_chunks`（基于 ChromaDB 的向量相似度搜索）推迟到 v2。`chunk_index.py` 文件保留但未注册到 tool registry。当前 agent 只有关键词搜索（search_documents）和全文 grep（grep_documents），缺少语义理解能力。

**影响**：对于同义词、概念性问题的检索效果差。

### 1.3 ~~Transcript 文件配置化未实现~~ ✅ 已实现

需求文档 7 设计了 `AgentConfig.enable_transcript: bool = False` 开关，使 transcript 文件可选（默认关闭）。已在 `ENABLE_TRANSCRIPT` 设置项中实现，用户可在"设置 → 文档聊天 → 检索与生成"中开关。

### 1.4 cite_sources 兜底机制未实现

需求文档 8 指出：若 LLM 跳过 `cite_sources` 工具调用，用户将看不到引用来源。设计了 runtime 强制兜底方案，但未实现。

### 1.5 路径优先分类算法未完整实现

需求文档 18 设计了"路径优先 + 自适应深度"算法（最长公共前缀、trie 构建、`min_group_size` 自适应剪枝），但实际 path 分类仍停留在一级目录粒度。

## 二、已审查需求文档中的遗留功能

### 2.1 AI 回复反馈（点赞/踩）

需求文档 15 将其列为 Phase 2 可选功能。用户无法对 AI 回复质量进行反馈，不利于后续优化 prompt 或 fine-tuning。

### 2.2 DocReader 内文档搜索（Cmd+F）

需求文档 15 将其列为 Phase 2 可选功能。长文档阅读时无法快速定位关键词。

### 2.3 键盘快捷键系统

需求文档 15 明确排除了键盘快捷键，建议单独立项。当前应用无全局快捷键支持（如 Cmd+N 新建对话、Cmd+K 搜索等）。

### 2.4 新用户引导流程

需求文档 15 排除了新用户 onboarding。当前首次进入只有 SetupWizard 配置 API key，缺少功能引导。

## 三、同类产品常见但本项目缺失的功能

### 3.1 对话导出

用户无法将有价值的对话导出为 Markdown / PDF / HTML 进行保存或分享。

### 3.2 对话历史搜索

聊天列表只支持按名称排序和拖拽重排，无法按内容关键词搜索历史对话。

### 3.3 跨知识库全局搜索

用户只能在单个集合内搜索文档，无法跨多个知识库进行全局检索。

### 3.4 文档增量更新

无法追踪网页文档的变化。URL 对应的页面更新后，只能删除旧文档重新爬取，无法做增量 diff 更新。

### 3.5 批量文档操作

文档多了以后管理成本高：缺少批量删除、批量移动分类、批量重新处理等操作。

### 3.6 模型连接测试

Settings 页面填写完 API key / Base URL / Model 后无法验证配置是否正确，只有到实际聊天时才会发现配置错误。

### 3.7 多用户 / 权限系统

天然单用户设计，无法团队共用同一实例。无用户认证、角色权限、知识库隔离等。

### 3.8 数据导入导出

无法备份或迁移整个应用数据（知识库、对话、设置）。换机器或重装时数据丢失。

## 四、代码卫生 / 技术债

### 4.1 遗留类型未清理

`backend/chat/models.py` 中的 `QueryIntent`、`ProcessingMode`、`RouterResult` 是旧 RAG pipeline（已被 agent 架构取代）的残留，应删除。

### 4.2 空目录

`orchestration-workflow/` 目录为空，无实际用途，应清理。

### 4.3 文档与实际不符

README / CLAUDE.md 提到 Electron 桌面端支持，但代码中无任何 Electron 相关文件。应移除相关描述或标注为"已废弃"。

### 4.4 Scrapy 爬虫未使用

`backend/crawler/scrapy_web_crawler.py` 存在于代码库中，但实际爬虫使用的是 `SimpleWebCrawler`（Requests + BeautifulSoup）。Scrapy 爬虫代码可能是早期实验产物，应确认是否需要保留。

## 五、建议优先级

| 优先级 | 项目 | 理由 |
|--------|------|------|
| **P1** | 模型连接测试 | 配置出错时用户无反馈，体验差 |
| **P1** | 向量语义搜索接入 Agent | 核心检索能力缺失，影响回答质量 |
| **P1** | 多 LLM 后端支持 | 单一供应商锁定，成本和灵活性受限 |
| **P2** | 对话导出 | 高频需求，实现简单 |
| **P2** | 对话历史搜索 | 对话多了以后无法回溯 |
| **P2** | 路径优先分类完整实现 | 需求 18 的核心算法未落地 |
| **P2** | cite_sources 兜底 | 影响引用来源的可靠性 |
| **P3** | DocReader 内搜索 | 长文档阅读体验 |
| **P3** | 批量文档操作 | 文档规模增大后的管理需求 |
| **P3** | 文档增量更新 | 追踪网页变化 |
| **P3** | 数据导入导出 | 数据可迁移性 |
| **P4** | 键盘快捷键 | 效率提升，非核心 |
| **P4** | 多用户系统 | 取决于是否有团队使用需求 |
| **P4** | 技术债清理 | 代码卫生，不影响功能 |
