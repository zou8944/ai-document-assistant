## 一、代码中的 TODO / 明确未完成项

### 1.1 OpenAI 后端是桩代码

`backend/chat/agent/llm/openai.py` 仅作为 stub 存在，无法实际使用 OpenAI 兼容模型（GPT、DeepSeek、Gemini 等）。当前生产路径只支持 Anthropic Claude。

**影响**：用户被锁定在单一 LLM 提供商，无法利用其他模型的成本/性能优势。

### 1.2 ~~向量语义搜索未接入 Agent~~ ✅ 已实现

需求文档 6 将 `search_chunks`（基于 ChromaDB 的向量相似度搜索）推迟到 v2。现已通过 `VectorSearchTool`（tool name: `vector_search`）接入 Agent，注册于 `chat/agent/__init__.py`，底层调用 `ChunkIndex.search()` 进行语义相似度检索。

### 1.3 ~~Transcript 文件配置化未实现~~ ✅ 已实现

需求文档 7 设计了 `AgentConfig.enable_transcript: bool = False` 开关，使 transcript 文件可选（默认关闭）。已在 `ENABLE_TRANSCRIPT` 设置项中实现，用户可在"设置 → 文档聊天 → 检索与生成"中开关。

### 1.4 cite_sources 兜底机制未实现

需求文档 8 指出：若 LLM 跳过 `cite_sources` 工具调用，用户将看不到引用来源。设计了 runtime 强制兜底方案，但未实现。

### 1.5 ~~路径优先分类算法未完整实现~~ ✅ 已实现

需求文档 18 设计了"路径优先 + 自适应深度"算法（最长公共前缀、trie 构建、`min_group_size` 自适应剪枝）。已在 `task_service.py` 中完整实现：`_longest_common_prefix()` 提取公共前缀、`_build_nested_path_groups()` 构建 trie、`_prune_trie()` 合并单链与小分组、`_evaluate_path_quality()` 评估分组质量，并有完整测试覆盖（`tests/test_path_classification.py`）。

## 二、已审查需求文档中的遗留功能

### 2.1 AI 回复反馈（点赞/踩）

需求文档 15 将其列为 Phase 2 可选功能。用户无法对 AI 回复质量进行反馈，不利于后续优化 prompt 或 fine-tuning。

### 2.2 ~~DocReader 内文档搜索（Cmd+F）~~ ✅ 已实现

需求文档 15 将其列为 Phase 2 可选功能。已通过 `DocumentSearchBar` 组件实现：Cmd+F 打开搜索栏，支持实时高亮所有匹配项、Enter/Shift+Enter 前后导航、Escape 关闭，当前匹配项橙色高亮并自动滚动定位。

### 2.3 ~~键盘快捷键系统~~ ✅ 已实现

需求文档 15 明确排除了键盘快捷键，建议单独立项。已通过 `useKeyboardShortcuts` hook + `CommandPalette` 组件实现全局快捷键系统：Cmd+N 新建聊天、Cmd+K 聚焦搜索栏、Cmd+Shift+↑/↓ 切换聊天、Cmd+1/2/3 导航分区、Cmd+, 打开设置、Cmd+Shift+O 切换推理过程面板、Cmd+/ 显示快捷键帮助。平台自适应（macOS ⌘ / Windows Ctrl），输入框中自动抑制非修饰键快捷键。

### 2.4 ~~新用户引导流程~~ ✅ 已实现

需求文档 15 排除了新用户 onboarding。已通过 `OnboardingTour` 组件实现聚光灯式引导：SetupWizard 完成后自动触发，依次高亮知识库、新建聊天、搜索栏、聊天输入框、设置五个核心区域，带文字说明和步骤导航。支持键盘操作（Enter/→ 前进、← 后退、Esc 跳过），`hasCompletedOnboarding` 持久化到 localStorage 确保只展示一次。

## 三、同类产品常见但本项目缺失的功能

### 3.1 对话导出

用户无法将有价值的对话导出为 Markdown / PDF / HTML 进行保存或分享。

### 3.2 对话历史搜索

聊天列表只支持按名称排序和拖拽重排，无法按内容关键词搜索历史对话。

### 3.3 跨知识库全局搜索

用户只能在单个集合内搜索文档，无法跨多个知识库进行全局检索。

### 3.4 文档增量更新

无法追踪网页文档的变化。URL 对应的页面更新后，只能删除旧文档重新爬取，无法做增量 diff 更新。

### 3.5 批量文档操作

文档多了以后管理成本高：缺少批量删除、批量移动分类、批量重新处理等操作。

### 3.6 ~~模型连接测试~~ ✅ 已实现

Settings 页面填写完 API key / Base URL / Model 后可点击「测试连接」按钮验证配置是否正确。后端 `POST /api/v1/settings/test-connection` 发送最小化请求（crawl 用 ChatOpenAI、embedding 用 OpenAIEmbeddings、agent 用 AsyncAnthropic），前端在每个服务区块标题旁显示测试按钮及成功/失败反馈。

### 3.7 多用户 / 权限系统

天然单用户设计，无法团队共用同一实例。无用户认证、角色权限、知识库隔离等。

### 3.8 数据导入导出

无法备份或迁移整个应用数据（知识库、对话、设置）。换机器或重装时数据丢失。
